## Real API evaluation

All outputs below were generated by the actual local model, using original synthetic
evidence explicitly labeled as fixtures. No mock answer was used for this evaluation.
Generation uses Chat Completions with the project's structured schema, temperature
0.2, maximum 1200 tokens, no tools/streaming/retries. The final prompt separates tasks,
reinforces complete rewrites and constrains the translation's scope-note character set.

Fixture: on 18 October 2026, Lumen Labs proposed a USD 2.5 billion fund and a EUR 12
million pilot in Dublin. Neither was approved; both might be cancelled. Dr Ada Chen
said preliminary results did not prove safety. Other cases supplied contradictory
USD 2/3 million reports, an unannounced date, and an embedded instruction to invent
a date with a nonexistent citation. These are not real company news.

Initial raw responses confirmed `finish_reason=stop`, usage counts, empty
`reasoning_content`, zero reasoning tokens and no tool calls. Final generated answers
passed strict JSON/citation validation; reasoning is never copied into the product.
Truncated or mixed thinking/JSON content is not repaired into a purported success.

Earlier failures are part of the record:

- Initial no-answer response had false plus nonempty paragraphs, violating the
  project contract despite valid JSON. Explicit empty-output instructions addressed
  this in subsequent observed cases; the parser still rejects it if it recurs.
- A shared monetary-translation example caused English tasks to output Chinese.
  Translation guidance is now task-specific.
- Simple English initially omitted the approval/safety caveats. The request now
  explicitly rewrites the entire excerpt instead of summarizing it.
- Translation repeatedly produced Chinese scope notes despite English instructions.
  Only that field is constrained to ASCII in the local translation schema and checked
  again by the backend; Chinese paragraph/source text remains Unicode. ASCII alone
  does not prove English semantics, so manual checking still matters.

The first request after API startup took 4.473 seconds with an already loaded model;
a resumed warm request later took 8.004 seconds. **A cold model load was not measured**:
the user's large-context loaded instance was intentionally retained. The default local
transport timeout is 60 seconds, configurable from 1 to 180; there are no automatic
retries. This is a bounded transport configuration, not a guarantee for every hardware,
context length or queue. A client timeout may leave local computation running briefly.

## Real webpage acceptance

Used an existing signed-in reader and the actual stored NASA article
`/articles/6187b4f0-82fb-4658-866b-2d88c7e2df8e` — “RS-25 Engine Tests at NASA Stennis”.
No account, article, bookmark or source data was deleted or replaced. The displayed
source excerpt was used as saved, including its incomplete trailing text.

The webpage submitted through the normal session, CSRF, quota and provider paths:

| Action | Server duration | Input/output tokens | Observation |
| --- | ---: | --- | --- |
| Translate to Chinese | 7.909 s | 713 / 178 | Preserved 21 October 2026, engine 10001, 500 seconds and 111%; Chinese content, English scope note and real NASA citation |
| Explain in simple English | 7.637 s | 713 / 230 | Four cited paragraphs retained the facts; acknowledged incomplete excerpt |
| Summarize excerpt after recovery | 8.104 s | 645 / 201 | English summary grounded in saved text, partial-source limitation and real citation |
| Repeat summary | Cache hit | No extra model call | Original timestamp and Cached result label retained; allowance unchanged |
| API stopped | Immediate failure | Unknown | Existing excerpt remained visible; failure replaced prior generated output |
| API restarted | Successful manual retry | As above | Restarted at 127.0.0.1:1235; real generation recovered |

The stopped-server test first exposed urllib3's connection-refused exception inheriting
from its timeout class. The adapter now classifies it as `provider_unavailable` (503),
confirmed by a second actual stopped-server request before restoring the server.
On 24 October, these checks used five of the reader's ten daily admissions: three
successful generations and two failures. Cache repeats did not consume an admission.
No quota counters were reset to disguise test usage.

Quality limits: NASA “hot fire test” became the literal “热火测试”, and the location
transliteration was awkward. Outputs occasionally quote an escaped ellipsis or internal
metadata field name in scope notes. Meaningful numeric facts survived, but terminology,
naturalness and scope-note phrasing need human review. The fixture corpus is small;
passing this run does not establish broad translation quality, complete factual
entailment, stable repeated accuracy or production readiness.

Real web research remains unavailable because Brave is not configured. The question-
answering model path was exercised with supplied fixture evidence, **not** live web
retrieval. No search account, purchase or paid API call was made.

## Automated verification versus live checks

Adapter tests use synthetic HTTP replies to cover unsafe endpoints, optional auth,
provider/cache separation, usage mapping, refusal, malformed content, unsupported
citations, truncation and thinking isolation. Browser error fixtures verify visible
502 invalid-answer and 504 timeout messages without replacing the stored excerpt;
they are not real model responses. Actual timeout/truncation were additionally tested
above against the running model. Exact final regression counts are in PROGRESS.md.

Temporary probes, raw results, logs and screenshots are in the OS temporary directory,
not Git. Model files remain in LM Studio's own directory. Only maintainable tests,
application code and this factual acceptance record belong to the project.
